# Security reports

Use sanitized, synthetic configurations when reporting a problem. Do not include real credentials, private server names, sensitive paths, or unredacted configuration files.

For a sensitive vulnerability, use **Security → Report a vulnerability** if private reporting is enabled on this repository. If it is unavailable, open a minimal public issue asking for a private reporting channel. Do not include exploit details or secrets in that request.

Include the affected version, expected and actual behavior, a minimal synthetic reproduction, and the likely impact. Risk findings in an audited configuration are not necessarily defects in this tool.

This project is an early release. Fixes target the latest published version; response times and security certification are not guaranteed.
